Spice for GitHub now presents canonical Spice declarations on every GitHub.com read-only code surface where they appear—without changing a single source byte.

![Spice for GitHub settings in dark mode](https://github.com/spice-framework/chrome/releases/download/v0.1.2/spice-for-github-settings-dark.png)

## What changed

- Spice rendering is no longer limited to `.go` file blobs. Canonical `// @` declarations are presented in file views, blame, commits, compare views, pull-request diffs, review snippets, and rendered markdown Go fences.
- Markdown documents such as `docs/getting-started.md` convert Spice samples in Go code fences the same way a `.go` file does. Ordinary markdown prose is left untouched.
- GitHub's current Files changed / commit DOM (including `.diff-text-inner` lines) is recognized, so PR and commit diffs highlight again after the 2026 review UI change.
- Display-line tokenization accepts leading indent and unified-diff `+`/`-` markers so copied and rendered source stay byte-identical.

## Source integrity and privacy

The extension changes presentation only. The original `// ` prefix stays in the DOM, copying returns the exact valid Go source, and raw views remain untouched. Processing is local to the browser; there is no telemetry, remote code, or hidden network request. The only permission is `storage`, used for display settings.
